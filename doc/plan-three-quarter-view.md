# 반측면(3/4 뷰) 추가 계획

작성일: 2026-09-25 · 관련: [설계 문서](design.md) · [진행 상황](progress.md)

정면과 측면 사이로 몸을 비스듬히 돌린 **반측면** 방향을 추가한다. 이 문서는 구현 전에 **기존 프로그램·파일·결과물과 문제없이 공존하는 방법**을 정리한다.

## 1. 목표와 범위

| 항목 | 내용 |
| --- | --- |
| 추가 방향 | 앞 반측면(왼쪽을 향함), 뒤 반측면(왼쪽을 향함) — 새로 그리는 방향 2개 |
| 반전 방향 | 앞 반측면(오른쪽), 뒤 반측면(오른쪽) — 지금의 우측면처럼 반전으로 자동 생성, 필요하면 파츠별로 따로 그리기 |
| 결과 | 4방향 캐릭터는 지금과 완전히 같고, 반측면을 켠 캐릭터만 8방향 |
| 범위 밖 | 원근에 따른 팔다리 길이 변화(단축) — 지금처럼 2D 회전만, 필요하면 각도 이미지·프레임 손보기로 보정 |

## 2. 호환성 원칙

1. **반측면은 선택 기능이다.** 캐릭터마다 "반측면 있음/없음"이 있고, 없으면 지금 프로그램과 한 픽셀·한 바이트도 다르지 않게 동작한다.
2. **기존 파일은 그대로 열리고, 저장해도 그대로다.** 반측면이 없는 프로젝트는 지금과 같은 형식(버전 1)으로 저장한다.
3. **새 기능을 쓴 파일만 형식 버전을 올린다.** 반측면이 있는 파일은 버전 2로 저장하고, 옛 프로그램은 이미 있는 검사(`FormatVersion`)로 "새 버전에서 만든 파일" 안내를 띄운다. 잘못 열리거나 멈추지 않는다.
4. **결과물 배치는 바뀌지 않는다.** 스프라이트 시트·JSON·GIF는 4방향이 기본이고, 8방향은 사용자가 고를 때만 기존 4줄 **뒤에** 붙는다.
5. **빠진 데이터는 정해진 규칙으로 채운다.** 반측면 그림이나 동작 트랙이 없어도 오류 없이 보이게 한다(4.3, 5절).

## 3. 현재 구조와 영향 지점

방향은 `Direction` 열거형과 `DirectionExtensions`(`Stored`, `All`, `Source`, `IsMirrored`)에 모여 있다. 우측면만 "좌측면의 반전"이라는 규칙이 여러 곳에 퍼져 있어서, 이 규칙을 일반화하는 것이 핵심이다.

| 위치 | 지금 | 바꿀 점 |
| --- | --- | --- |
| `Core/Rigging/Direction.cs` | 4개 값, `Stored` = 정면·좌측면·후면, 반전은 우측면만 | 값 4개 추가(끝에), 반전 짝 표(`Source`) 일반화, 캐릭터별 방향 목록 |

| `Core/Rigging/RightViewChange.cs` | 우측면 따로 그리기 되돌리기 | 반전 방향 전체로 일반화 (이름 유지하고 방향 인자 추가) |

## 4. 데이터 모델

### 4.1 방향 값

```csharp
public enum Direction
{
    Front, Left, Right, Back,               // 기존 — 순서·이름 그대로
    FrontLeft, FrontRight, BackLeft, BackRight, // 추가 — 반드시 끝에
}
```

- 기존 값의 순서를 바꾸지 않는다. 손보기 픽셀 저장 순서(`OrderBy(f => f.Direction)`)와 시트 줄 순서가 지금과 같게 유지된다.
- 파일 키는 지금처럼 소문자 이름이다: `frontleft`, `frontright`, `backleft`, `backright`.
- 반전 짝: `Right → Left`, `FrontRight → FrontLeft`, `BackRight → BackLeft`. `Source()`와 `IsMirrored()`는 이 표로 계산한다.

### 4.2 캐릭터별 방향 목록

`DirectionExtensions.Stored`/`All` 고정 목록 대신 캐릭터가 방향 목록을 가진다.

| 속성 | 반측면 없음 | 반측면 있음 |
| --- | --- | --- |
| `character.StoredDirections` | 정면·좌측면·후면 | + 앞 반측면(왼)·뒤 반측면(왼) |
| `character.Directions` (표시 순서) | 정면·좌측면·우측면·후면 | + 앞 반(왼)·앞 반(오)·뒤 반(왼)·뒤 반(오) |

기존 정적 목록 `Stored`/`All`은 "4방향 기본값"으로 남겨 두어 호출부를 한 번에 바꾸지 않아도 되게 하고, 호출부를 하나씩 캐릭터 목록으로 옮긴다.

### 4.3 반측면 켜기·끄기

- **켜기** (`반측면 추가`, 되돌리기 가능): 파츠마다 앞 반측면은 정면 뷰, 뒤 반측면은 후면 뷰의 **복사본**으로 시작한다(관절·레이어·각도 이미지·장착점 포함, `RightViewChange.CopyOf`와 같은 방식). 사용자가 그 위에 다시 그린다.
  - 마네킹 템플릿에서 시작한 새 프로젝트는 템플릿의 반측면 파츠를 쓴다(7절).
- **끄기**: 반측면 뷰·트랙·손보기 픽셀을 지운다. 되돌리기 가능하며, 저장하면 다시 버전 1 파일이 된다.

## 5. 애니메이션

### 5.1 트랙과 대체 규칙

- 반측면 트랙은 선택이다. 트랙이 비어 있으면 **앞 반측면은 정면 트랙, 뒤 반측면은 후면 트랙**을 그대로 재생한다.
  - 이유: 섞은 값은 사용자가 예측하기 어렵고, 비워 두면 "아직 안 만든 방향"이 정면과 같게 보여 알아보기 쉽다.
- `AnimationClip.Evaluate`만 이 규칙을 알고, 저장 파일에는 실제로 있는 키만 쓴다.

### 5.2 초안 만들기

- `반측면 동작 초안` 명령: 정면과 측면 키를 프레임별로 반씩 섞어(`AnimationClip.Blend`, t = 0.5) 반측면 트랙을 채운다. 몸 이동량도 섞는다.
- 기본 동작 6종의 반측면 트랙은 이 초안을 만든 뒤 마네킹으로 다듬어 `animations.json`에 넣는다.
- **시험 결과 (2026-09-25, 예시 캐릭터 2개):** 대기·걷기·달리기·점프처럼 정면과 측면이 **같은 관절**을 움직이는 동작은 초안이 자연스럽다 (다리가 비스듬히 앞뒤로 움직임). 손 흔들기처럼 정면은 오른팔, 측면은 가까운 왼팔을 쓰는 동작은 섞으면 두 팔이 반쯤 들린 모습이 되어 **손으로 만들어야** 한다. 초안 명령은 이미 키가 있는 반측면 트랙을 덮어쓰지 않는다.

### 5.3 동작 가져오기

| 보내는 쪽 → 받는 쪽 | 처리 |
| --- | --- |
| 4방향 → 4방향 | 지금과 같음 |
| 4방향 → 8방향 | 반측면 트랙 없음 → 대체 규칙으로 재생, 필요하면 초안 만들기 |
| 8방향 → 4방향 | 반측면 트랙은 버림 (안내 문구에 표시) |
| 8방향 → 8방향 | 모두 가져옴 |

## 6. 저장·내보내기

### 6.1 `.dotchar`

| 경우 | `project.json` `formatVersion` | `skeleton.json` | `animations.json` |
| --- | --- | --- | --- |
| 반측면 없음 | 1 (지금과 같음) | `front`/`left`/`back`(+`right`) | 트랙 `front`/`left`/`back` |
| 반측면 있음 | 2 | + `frontleft`/`backleft`(+ 따로 그린 `frontright`/`backright`) | + `frontleft`/`backleft` 트랙(있는 것만) |

- 새 프로그램은 버전 1·2를 모두 읽는다.
- 옛 프로그램은 버전 2 파일에서 이미 있는 "새 버전에서 만든 파일입니다" 오류를 띄운다. `animations.json`의 모르는 방향 오류까지 가지 않는다.

### 6.2 스프라이트 시트·JSON·GIF

- **기본은 4방향**: 반측면이 없거나 사용자가 4방향을 고르면 지금과 같은 파일이 나온다.
- **8방향을 고르면**: 동작마다 8줄이다. 순서는 `front, left, right, back`(기존 4줄 그대로) 뒤에 `frontleft, frontright, backleft, backright`를 붙인다.
  - 기존 4줄의 위치를 행 번호로 읽던 게임 엔진은 그대로 동작한다.
  - 메타데이터 JSON은 `directions`에 키 4개를 더한다. 기존 키와 필드는 그대로다.
- GIF는 고른 방향 수만큼 옆으로 붙인다(4 또는 8칸).
- 명령줄 일괄 내보내기에 `--directions 4|8`을 추가하고, 기본값은 4다.
- 설정의 "시트와 함께 JSON 쓰기"처럼 내보내기 방향 수를 설정(`AppSettings`)에 저장한다. 기본값은 4다.

## 7. 템플릿(마네킹)

- `mannequin/make_chibi_parts.py`에 `view_front_left`, `view_back_left`를 추가한다.
- **시험한 만드는 법 (2026-09-25, scratchpad 시안 — 저장소에는 아직 없음):**
  - 관절 위치: 몸 중심선 기준으로 가까운 쪽 관절은 정면 거리의 0.85배, 먼 쪽은 0.55배로 모은다. 팔다리 굵기는 그대로. 앞 반측면(왼쪽을 향함)은 먼 쪽 = 캐릭터 오른쪽(`_r`, 화면 왼쪽), 뒤 반측면은 먼 쪽이 화면 오른쪽.
  - 몸통·허리·골반: 정면 윤곽을 같은 비율로 모으고, 가슴 앞면을 향하는 쪽으로 1px 내민다.
  - 머리: 정면 머리(귀 없음)와 측면 머리의 가로 폭을 줄마다 반씩 섞는다 (턱이 향하는 쪽으로 옮겨 감). 앞 턱선 아래는 목만 남기고, 3줄 평균으로 윤곽을 매끄럽게.
  - 발: 향하는 쪽으로 조금 옮긴 타원.
  - 그리기 순서 (뒤→앞): 먼 팔 → 먼 다리 → 가까운 다리 → 골반·허리·가슴·머리 → 가까운 팔.
  - **몸통:** 정면보다 폭이 좁고, 가슴·골반이 향하는 쪽으로 조금 치우친다.
  - **팔다리:** 먼 쪽 팔다리는 몸 뒤로 일부 가려지게 그리기 순서를 조정한다.
  - **머리:** 얼굴이 향하는 쪽으로 턱선을 옮기고, 먼 쪽 귀는 보이지 않게 한다.
  - **후면 반측면:** 뒤통수와 등을 기준으로 같은 규칙을 적용한다.
- 관절 원 있는/없는 템플릿 모두에 생성한다. `skeleton.json`에는 새 키만 추가하므로, 기존 3방향 템플릿 파일을 읽는 코드와 호환된다.
- 새로 만들기 창(만들 동작 고르기)에 **"반측면 포함"** 체크를 추가하고, 기본은 끔으로 둔다. 끈 채로 만든 프로젝트는 버전 1이라 옛 프로그램과도 주고받을 수 있다.

## 8. 화면(UI)

- **방향 목록**(도구 창)과 **미리보기 두 곳**은 캐릭터의 방향 목록을 반복해서 그린다. 4방향 캐릭터는 지금과 똑같이 보인다.
- **단축키:** 5~8을 새 방향에 기본으로 준다. 이미 5~8을 다른 기능에 쓰고 있으면, 단축키 설정의 기존 겹침 처리 규칙을 따른다.
- **메뉴(보기 또는 편집):** `반측면 추가`, `반측면 지우기`, `반측면 동작 초안`을 넣는다.
- **반전 끊기:** 파츠 창의 "우측면 따로 그리기"는 반전 방향(우측면·앞 반 오른쪽·뒤 반 오른쪽)에서 모두 보이게 한다. 문구는 "반전 끊고 따로 그리기"로 바꾼다.
- **대칭 그리기:** 반측면에서는 꺼진 상태로 표시한다. 지금 측면과 같다.
- **번역:** 새 문구는 `en.json`에 추가하고 `scripts/check-translations.py`로 빠진 것을 확인한다.

## 9. 작업 순서

진행 상황: ① 완료 ([패치노트](patchnotes/2026-09-25-direction-model.md)). ④의 반측면 몸·머리는 scratchpad 시안으로 먼저 시험했다 (위 7절, 저장소에는 아직 없음). 반측면 눈을 다듬으려면 필요한 **눈 위치 옮기기**를 ③ 전에 추가한다. 실제 작업은 세션 작업 브랜치(`claude/work-environment-setup-a3u93e`)에서 하고 있으며, 아래 브랜치 이름은 `main`에 나눠 병합할 때의 단위다. 구현하면서 정한 이름 — `Direction.FrontLeft`·`FrontRight`·`BackLeft`·`BackRight`, `Character.HasThreeQuarter`·`StoredDirections`·`Directions`, `ThreeQuarterViews.Enable`·`Disable`, `ProjectFile.VersionFor`.

각 단계는 저장소 규칙대로 `feature/...` 브랜치에서 작업한다. 단계마다 테스트·스크린샷·패치노트를 남기고 `main`에 병합한다. 앞 단계만 병합돼도 프로그램이 정상 동작하도록 순서를 잡았다.

| 단계 | 브랜치 | 내용 | 병합 후 사용자에게 보이는 변화 |
| --- | --- | --- | --- |
| ① | `feature/direction-model` | 방향 값 추가, 반전 짝 일반화, 캐릭터별 방향 목록, 선택 뷰·트랙, 대체 규칙, 형식 버전 규칙 | 없음 (4방향 그대로) |
| ② | `feature/export-directions` | 시트·JSON·GIF·명령줄의 방향 수 선택 | 없음 (기본 4방향) |
| ③ | `feature/three-quarter-ui` | 방향 목록·미리보기 반복, 단축키, 반측면 추가·지우기, 반전 끊기 일반화 | 반측면 켜기 가능 (정면 복사본에서 시작) |
| ④ | `feature/three-quarter-template` | 마네킹 반측면 파츠, 기본 동작 반측면 트랙, 새로 만들기 "반측면 포함" | 새 프로젝트를 반측면 마네킹으로 시작 |
| ⑤ | (각 단계에 포함) | 설계 문서 4.1·4.4 표 갱신, 진행 상황, 패치노트 | — |

## 10. 테스트 계획

### 10.1 회귀 (기존과 같아야 함)

- **기존 테스트:** 121개가 모두 통과해야 한다.
- **기준 파일 테스트:** 단계 ① 전에 지금 버전으로 저장한 4방향 프로젝트(손보기·각도 이미지·장착점·레이어·우측면 따로 그리기를 모두 포함)를 `tests/.../Fixtures`에 넣는다. 새 코드로 다음을 확인한다.
  - 불러오기 → 저장 결과가 원본과 같다 (JSON은 내용 비교, PNG는 픽셀 비교)
  - 전체 시트·JSON·GIF 내보내기 결과가 지금 버전의 출력과 픽셀 단위로 같다
- **형식 버전:** 반측면이 없는 프로젝트는 항상 `formatVersion: 1`로 저장된다.

### 10.2 새 기능

- **저장·불러오기:** 반측면 켜기 → 저장(버전 2) → 불러오기 결과가 같다. 끄기 → 저장하면 버전 1이 된다.
- **대체 규칙:** 트랙이 빈 반측면은 정면·후면과 같은 프레임을 만든다.
- **반전:** 반측면 오른쪽은 왼쪽 합성을 좌우 반전한 것과 같다(따로 그리지 않은 파츠). 장착점 좌표도 반전된다.
- **동작 가져오기:** 5.3의 네 경우를 모두 확인한다.
- **8방향 시트:** 앞 4줄이 4방향 시트와 같고, JSON 기존 키가 그대로다.
- **옛 버전 읽기:** 버전 2 파일을 지금 버전(1까지 읽음)의 `ProjectFile.Load`로 열면 "새 버전" 오류가 난다. 테스트에서는 버전 값을 조작해 재현한다.

### 10.3 앱 확인

- 4방향 프로젝트 화면이 이전과 같은지 스크린샷으로 비교한다.
- 반측면 켜기·그리기·재생·내보내기·되돌리기를 앱에서 직접 확인한다.
